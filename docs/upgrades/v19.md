# Upgrade to Umbraco 19

From `18.0.0` (range `[18.0.0, 19.0.0)`) to `19.0.0-beta1` (tag `release-19.0.0-beta1`).
Branch `v19/feature/umbraco-19-upgrade`, cut from `origin/v18/dev` (`46c52df`); PR into `v19/dev`.

**Targets CMS release:** `release-19.0.0-beta1`. Package versions carry no pre-release
suffix (see Decisions); they aren't published until CMS 19 is on NuGet.

## Inventory

What CMS 19 changes that this repo actually uses. Sources are the CMS diff
`release-18.0.0..release-19.0.0-beta1`, the 19.0.0-beta1 release notes, and
`19/umbraco-cms/get-started/upgrading-and-migrating/version-specific.md` in UmbracoDocs.
The upgrade floor on the docs page is 16.4, so the hop from 18 is allowed.

### Framework and shared dependencies

- **.NET 10 → .NET 11** (beta1)\
  Source: `release-19.0.0-beta1:Directory.Build.props` (`net11.0`, `runtime-async=on`)\
  Hits: 9 `src/*/*.csproj`, 2 `tests/*/*.csproj`, the testsite csproj, `global.json`
  (SDK `11.0.100-rc.3.26522.148`, the build CMS 19 beta1 depends on).
- **Umbraco.Cms.* floor `[18.0.0, 19.0.0)` → `[19.0.0-beta1, 20.0.0)`** (beta1)\
  Hits: `Directory.Packages.props:14`; testsite `Directory.Packages.props:7-8` (pins 18.0.0).
  Expect NU5104 while the floor is a pre-release.
- **No direct Microsoft.\*, OpenIddict, Microsoft.OpenApi or Swashbuckle references.**
  Everything shared with the CMS comes in transitively (`Microsoft.Extensions.*`
  11.0.0-rc.3.26522.148). `Algolia.Search 6.13.0` only needs `Newtonsoft.Json >= 13.0.1`
  (resolves 13.0.3). No conflict.
- **`@umbraco-cms/backoffice` 18.0.0 → 19.0.0-beta1**, peer `@hey-api/openapi-ts >=0.99.0`
  (we pin `^0.97.0`, which can't satisfy it). UUI 2.0.2 → 2.1.1.\
  Hits: 8 `src/*/Client/package.json`, root `package-lock.json`.

### Won't compile on 19

- **`IDataEditor.PropertyIndexValueFactory`, `IPropertyIndexValueFactory` and
  `Umbraco.Cms.Core.PropertyEditors.IndexValue` removed** (beta1)\
  Source: umbraco/Umbraco-CMS#23321 (`d6c5c283c35`); docs "Search indexing".
  Replacement: `IPropertyValueHandler` / `Umbraco.Cms.Core.Search.Indexing`.\
  Hits: `Search.Algolia/Services/AlgoliaSearchPropertyIndexValueFactory.cs:46`; the public
  `Search.Algolia/Converters/IAlgoliaIndexValueConverter.cs:19` and all 7 converters'
  `ParseIndexValues(IProperty, IndexValue)`.
- **`JsonPatch.Net` (and with it `Json.More`) no longer comes in via `Umbraco.Cms.Api.Management`** (beta1)\
  Source: umbraco/Umbraco-CMS#24015 (`a10667dee34`)\
  Hits: `Crm.Dynamics/Editors/DynamicsFormPickerValueConverter.cs:1,37` (`TryGetValue(..., out _, out _)`).
  Replacement: System.Text.Json `TryGetPropertyValue`.

### Compiles, behaves differently

- **Single/multiple editor split: single media pickers move to `Umbraco.MediaPicker.Single`,
  single dropdowns to `Umbraco.DropDown.Single`; MediaPicker3 always returns a collection** (beta1)\
  Source: umbraco/Umbraco-CMS#23853 (`37e87e8725c`); docs "Single and multiple value editors".\
  Hits:
  - Zapier `Services/Parsers/MediaParser.cs:14-16` (`as MediaWithCrops` is now always null) and
    `ZapierContentFactory.cs:11,13,16` (only knows `MediaPicker3`/`DropDownListFlexible`).
  - Algolia `Converters/UmbracoMediaPickerConverter.cs:16` (no longer matches single pickers;
    stored JSON is unchanged).
- **Blocks can reference reusable Library content** (beta1)\
  Source: umbraco/Umbraco-CMS#22448\
  Hits: Algolia `UmbracoBlockValueConverterBase.cs:79-103` only walks `contentData`, so
  referenced Library content isn't indexed.
- **Cookie-based backoffice auth: `UmbOpenApiConfiguration.token` deprecated (removal in 21),
  `token()` returns undefined, config now carries `credentials: 'include'`** (beta1)\
  Source: umbraco/Umbraco-CMS#23484 (`b8d37e7b0f2`); `@typescript-eslint/no-deprecated` on 19.\
  Hits: `auth: config?.token` in all 8 `Client/src/index.ts` (Hubspot:24, Zapier:18,
  Shopify:20, ActiveCampaign:21, Dynamics:20, GoogleSearchConsole:18, Semrush:20, Algolia:16).
- **`AllowEditInvariantFromNonDefault` setting removed** (beta1)\
  Source: docs page\
  Hits: testsite `appsettings.json:20`.
- **Property editor UI groups localized (`#propertyEditorUIGroups_*`)** (beta1)\
  Source: umbraco/Umbraco-CMS#22196\
  Hits: our `pickers`/`common` groups merge with core in English but form a separate
  English-named group in other UI languages. Cosmetic.

### Obsolete APIs

- **`PropertyCacheLevel.Snapshot` obsolete ("Caching no longer supports snapshotting"), no
  replacement named** (18.x, still obsolete at 19). HybridCache treats `Snapshot` as `None`
  (`release-19.0.0-beta1:src/Umbraco.PublishedCache.HybridCache/PublishedProperty.cs:202`),
  so the behaviour-preserving replacement is `None`; pure converters can use `Element`\
  Source: CS0618 on 18.2.0\
  Hits: `Commerce.Shopify/Configuration/ShopifySettings.cs:15`,
  `Crm.ActiveCampaign/Editors/ActiveCampaignFormPickerValueConverter.cs:21`,
  `Crm.Dynamics/Editors/DynamicsFormPickerValueConverter.cs:23`,
  `Crm.Hubspot/Editors/FormPickerValueConverter.cs:13`.
- The second CS0618 build on 19 and the spike compile are pending a .NET 11 SDK on the build
  machine; they run as part of the bump task.

## Decisions

- 06-11-2026: Package versions are the new major with no pre-release suffix: Hubspot 10.0.0,
  ActiveCampaign 8.0.0, Dynamics 7.0.0, Shopify 7.0.0, Algolia 8.0.0, Semrush 6.0.0,
  GoogleSearchConsole 4.0.0, Zapier 7.0.0, Cookiebot 5.0.0. Dev builds still get NBGV's
  `-preview` suffix off the public branches; nothing is published until CMS 19 is on NuGet.
- 06-11-2026: `IAlgoliaIndexValueConverter.ParseIndexValues(IProperty, IndexValue)` →
  `(IProperty, string? culture)`.
- 06-11-2026: Algolia doesn't index Library-referenced block content yet; known gap, follow-up.
- 06-11-2026: `Snapshot` → `None`/`Element`, not `Elements`: `Elements` would cache live
  Shopify product data site-wide until the next publish (reviewer finding on task 1).
- 06-11-2026: Algolia runs a matching converter before the fallback, so the media picker
  converter now runs. On 18 `MediaPicker3` used `NoopPropertyIndexValueFactory`, so media fields
  indexed `""` and the converter was dead (backport candidate).
- 06-11-2026: Single Block gets its own `UmbracoSingleBlockConverter` (new public class), same
  list-of-strings shape as Block List/Grid. 18 indexed one concatenated summary; a Single Block
  nested in Block List/Grid stays skipped, as on 18.
- 06-11-2026: Algolia date/time values are formatted with the invariant culture; 18 used the
  current culture (`08.30.00` under Danish) (backport candidate).
- 06-11-2026: `AlgoliaSearchPropertyIndexValueFactory` keeps its `IContentTypeService`
  constructor parameter, now unused, so subclasses still compile.
- 06-11-2026: `main-v19` is created when the first v19 release is cut, not now.

## Breaking changes for consumers

- **Algolia:** `IAlgoliaIndexValueConverter.ParseIndexValues` signature changes (the CMS type
  it took is removed). Custom converters must be updated.
- **All packages:** require Umbraco CMS 19 and net11.0.

## Backport candidates

- **Algolia indexes media picker fields as an empty string** (task 3 commit).  On the current major: yes (`MediaPicker3` has a Noop index factory on 18). Class: would break
  a patch release (changes indexed output). Target line: v18/dev. Not picked yet.
- **Algolia time values depend on the server culture** (task 3 commit).  On the current major: yes. Class: safe for a patch release only on non-English servers'
  benefit; changes output there. Target line: v18/dev. Not picked yet.
